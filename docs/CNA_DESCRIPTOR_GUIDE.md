# CNA Descriptor Programming Guide

How to implement bespoke NPU operations using the CNA (Convolution Neural
Accelerator) descriptor API, and wire them into PyTorch and JAX frontends.

The CNA is the matrix-multiply unit inside the RK3588 NPU. Instead of
synthesizing regcmd bytes from captured .rknn templates (the
[regcmd codegen](NPU_REGCMD_REFERENCE.md) path used for elementwise ops), the
CNA descriptor API programs the hardware directly with a register list. This
supports **arbitrary K and N dimensions** (not just the 5 shapes baked into
templates) and is the workhorse for every matmul in GPT-2, ViT, and beyond.

## 1. What the CNA Actually Does

The CNA is a 1x1 direct-convolution engine. Matrix multiplication
`Y = X @ W` where X is `[M, K]` and W is `[K, N]` is expressed as:

```
Y[m, n] = sum_k X[m, k] * W[k, n]
```

In convolution terms:
- **Input** X is treated as an M-element "batch" of 1x1 feature maps with
  K input channels.
- **Weight** W is treated as a 1x1 kernel with K input channels and N
  output channels.
- **Output** Y is an M-element batch of 1x1 feature maps with N output
  channels.

The CNA reads input and weight from DRAM via DMA, computes the
multiply-accumulate in its internal CBUF (channel buffer), and writes the
result back to DRAM. The entire operation is described by a flat list of
register writes — the "descriptor" or "task" — plus three DMA addresses.

### Performance characteristics

| Metric | Value |
|--------|-------|
| NPU DMA bandwidth | ~1.0 GB/s (DRAM), ~3.0 GB/s (L3 cache snoop) |
| M=1 matmul (768x768) | 0.22 ms (weight DMA dominates) |
| M=64 matmul (768x768) | 0.69 ms |
| M=1 matmul (768x3072) | 0.63 ms |
| Precision | fp16 inputs, fp32 accumulate, fp16/fp32 output |

For autoregressive decode (M=1), the NPU is **DMA-bound**: the weight
matrix is the bottleneck, and the single input vector is negligible.
This is why KV caching (M=1 decode) is so effective — you pay the weight
DMA once per token regardless of M.

## 2. The Five BOs

Every CNA matmul uses five buffer objects (BOs) allocated via DRM ioctls:

```
┌─────────────────────────────────────────────────────────┐
│  BO          │ Flags │ Size                  │ Purpose  │
├──────────────┼───────┼───────────────────────┼──────────┤
│  regcmd (rc) │ 0x403 │ 1024 bytes            │ Register │
│              │       │                       │ op list  │
│  task (tk)   │ 0x40b │ 4096 bytes            │ Task     │
│              │       │                       │ header   │
│  input (in)  │ 0x403 │ M4*Kt*2 + 4096        │ X (fp16) │
│  weight (wt) │ 0x403 │ n_tiles*N*Kta*2+4096  │ W (fp16) │
│  output (out)│ 0x403 │ M4*max_N*4 + 4096     │ Y (fp32) │
└─────────────────────────────────────────────────────────┘
```

- **M4** = M padded up to a multiple of 4 (see [§5](#5-critical-hardware-constraints)).
- **Kt** = K rounded up to a multiple of 32, capped at 768.
- **Kta** = Kt rounded up to a multiple of 32 (always equals Kt in practice).

The `regcmd` BO holds the 112-entry register list generated by
`cna_gen_task()`. The `task` BO is a 40-byte header that tells the NPU
where to find the regcmd and how many entries it has. The three data BOs
hold the actual input, weight, and output.

### BO allocation

```c
// Create a BO: ioctl(fd, CNA_CREATE, {flags, size, ...}) -> handle, obj, dma
// Map it:      ioctl(fd, CNA_MAP, {handle}) -> mmap offset
//              mmap(NULL, size, PROT_READ|PROT_WRITE, MAP_SHARED, fd, offset)
```

Each BO has three identifiers:
- **handle**: DRM GEM handle (per-fd)
- **obj_addr**: kernel object address (used for sync/submit)
- **dma_addr**: NPU-visible DMA address (written into regcmd entries)

The `dma_addr` is what goes into the CNA register task. It is assigned by
the IOMMU and is NOT the CPU virtual address.

### The CNA context struct

```c
typedef struct {
  int fd;
  // BO handles, obj_addrs, dma_addrs, mmap pointers for all 5 BO types
  uint32_t rc_h, tk_h, in_h, wt_h[MAX_NW], out_h;
  uint64_t rc_obj, tk_obj, in_obj, wt_obj[MAX_NW], out_obj;
  uint64_t rc_dma, tk_dma, in_dma, wt_dma[MAX_NW], out_dma;
  void *rc_mm, *tk_mm, *in_mm, *wt_mm[MAX_NW], *out_mm;
  // Geometry
  int M, max_K, max_N, n_w;
  int wt_K[MAX_NW], wt_N[MAX_NW];     // per-weight actual dimensions
  int wt_Kt[MAX_NW], wt_ntiles[MAX_NW], wt_tile_bytes[MAX_NW];
} CNAContext;
```

`MAX_NW` is 144 (one weight slot per matmul in a 12-layer GPT-2 with hybrid
fused QKV+fc and 4 decomposed proj tiles = 7 weights/layer x 12 = 84, plus
headroom).

## 3. The Register Task (cna_gen_task)

The core of the CNA descriptor is a flat array of 112 `uint64_t` entries,
each encoding a single register write:

```c
#define NPUOP(op, val, reg) \
  (((uint64_t)(op & 0xffff) << 48) | \
   ((uint64_t)(val & 0xffffffff) << 16) | \
   (uint64_t)(reg & 0xffff))
```

- **op** (bits 48-63): operation type. `0x1001` = DPU register write,
  `0x0201` = CNA register write, `0x0801` = core data-out config.
- **val** (bits 16-47): 32-bit register value.
- **reg** (bits 0-15): 16-bit register address.

### Register map (key registers only)

| #  | Register   | Address | Formula | Purpose |
|----|-----------|---------|---------|---------|
| 0  | DPU_S_POINTER | 0x4004 | 0xE | DPU pointer init |
| 1  | CNA_CONV_CON1 | 0x100C | `((2&7)<<7)|((2&7)<<4)` | Conv mode (1x1) |
| 2  | CNA_CONV_CON2 | 0x1010 | `((M+1)&0x3FF)<<4` | Batch + stride |
| 4  | CNA_DATA_SIZE0 | 0x1020 | `(1<<16)|M` | Output rows = M, groups = 1 |
| 5  | CNA_DATA_SIZE1 | 0x1024 | `((K-1)<<16)|K` | Input channels = K |
| 7  | CNA_DATA_SIZE3 | 0x102C | `M` | Surface stride |
| 8  | CNA_WEIGHT_SIZE0 | 0x1030 | `K*2*N` | Weight DMA amount (bytes) |
| 9  | CNA_WEIGHT_SIZE1 | 0x1034 | `K*2` | Weight DMA stride |
| 10 | CNA_WEIGHT_SIZE2 | 0x1038 | `(1<<24)|(1<<16)|N` | Weight cube dims |
| 11 | CNA_CBUF_CON0 | 0x1040 | `((wb&0xF)<<4)|(fb&0xF)` | CBUF bank split |
| 12 | CNA_CBUF_CON1 | 0x1044 | `ceil(K/32)` | Data entries |
| 21 | CNA_FEATURE_DATA_ADDR | 0x1070 | `in_dma` | Input DMA address |
| 24 | CNA_DMA_CON1 | 0x107C | 4 | DMA step |
| 25 | CNA_DMA_CON2 | 0x1080 | `4*((M/4)-1)` | DMA stride threshold |
| 30 | CNA_DCOMP_ADDR0 | 0x1110 | `wt_dma` | Weight DMA address |
| 50 | CORE_DATAOUT_SIZE_0 | 0x3014 | `(M-1)<<16` | Core data-out rows |
| 57 | DPU_DST_SURF_STRIDE | 0x4020 | `out_dma` | Output DMA address |
| 58 | DPU_DST_SURF_STRIDE1 | 0x4024 | `M<<4` | Output stride |
| 60 | DPU_DATA_CUBE_HEIGHT | 0x4034 | `M-1` | Output height |
| 62 | DPU_DATA_CUBE_WIDTH | 0x403C | `((N-1)<<16)|(N-1)` | Output width |
| 105 | PC_OPERATION_ENABLE | 0x0014 | 0 | Trigger |

### CBUF bank allocation (register 11)

The CNA's internal channel buffer (CBUF) has 12 banks. They are split
between feature data (input) and weight:

```c
uint32_t fd_bytes = M * K * 2;        // fp16 input size
uint32_t fd_banks = (fd_bytes + 32767) / 32768;
if (fd_banks < 1) fd_banks = 1;
uint32_t wt_banks = 12 - fd_banks;
// Register value: ((wt_banks & 0xF) << 4) | (fd_banks & 0xF)
```

For M=1, K=768: fd_bytes = 1536, fd_banks = 1, wt_banks = 11.
For M=64, K=768: fd_bytes = 98304, fd_banks = 3, wt_banks = 9.

The input always fits in 1-3 banks (it's small). The weight gets the rest.

### The task header

After filling the regcmd BO, you write a 40-byte task header:

```c
uint8_t *tk = task_mm;
memset(tk, 0, 40);
*(uint32_t*)(tk + 8)  = 0xd;       // regcmd entry count minus 8
*(uint32_t*)(tk + 12) = 0x300;     // flags
*(uint32_t*)(tk + 16) = 0x1ffff;   // mask
*(uint32_t*)(tk + 24) = 112 - 8;   // regcmd size in entries
*(uint64_t*)(tk + 32) = rc_dma;    // regcmd BO DMA address
```

### Submit

```c
uint8_t sub[104]; memset(sub, 0, 104);
*(uint32_t*)(sub + 0)  = 1 | 4;    // core mask
*(uint32_t*)(sub + 4)  = 6000;     // timeout
*(uint32_t*)(sub + 12) = 1;        // n_tasks
*(uint64_t*)(sub + 24) = tk_obj;   // task BO obj_addr
*(uint32_t*)(sub + 56) = 1;
*(int32_t*)(sub + 60)  = -1;       // fence
*(uint32_t*)(sub + 64) = 0;
*(uint32_t*)(sub + 68) = 1;
ioctl(fd, CNA_SUBMIT, sub);
```

Use `flags = 1 | 4` (non-blocking submit on core 0). After submit, flush
the output BO cache and read the result.

## 4. Memory Layouts You Must Get Right

The CNA does NOT use a simple row-major layout. The data is tiled into the
CBUF according to hardware-specific grouping. Getting this wrong produces
silently wrong results that pass shape checks but fail numerical checks.

### Weight layout: weight_fp16_off

The weight matrix W `[K, N]` must be transposed and tiled into the CBUF
order. The CNA computes `Y = W_cna @ X_cna = (X @ W)^T`, so `W_cna[n][k]`
must be `W[k][n]`.

```c
static int weight_fp16_off(int C, int k, int c) {
  int kpg = ((k - 1) / 16);       // output group (16 outputs per group)
  int cpg = ((c - 1) / 32);      // input group (32 inputs per group)
  return ((cpg * 32) * 16) + (kpg * 16 * C) + ((c - 1) % 32) + (((k - 1) % 16) * 32);
}
```

Parameters (1-indexed):
- `C` = Kta (K rounded up to 32)
- `k` = output index (1..N)
- `c` = input index (1..K)

The weight value stored at offset `(C, k, c)` is `W[c-1][k-1]` = `w[(c-1)*N + (k-1)]`:

```c
for (int n = 1; n <= N; n++)
  for (int k = 1; k <= Kt2; k++) {
    int sk = ks + k - 1;  // global input index (0-indexed)
    if (sk < K)
      tile[weight_fp16_off(Kta2, n, k)] = w[sk * N + (n - 1)];  // W^T layout
  }
```

> **Common mistake**: using `w[(n-1)*K + sk]` (reads W[n][k] instead of
> W[k][n]). This works for square matrices by accident (the transpose
> is "almost right" for symmetric patterns) but produces garbage for
> non-square weights like 768x2304.

### Input layout: feature_data_off

```c
static int feature_data_off(int C, int H, int W, int C2, int c, int h, int w) {
  int plane = (c - 1) / C2;
  int src = plane * H * W * C2;
  int off = (c - 1) % C2;
  return src + C2 * ((h - 1) * W + (w - 1)) + off;
}
```

For 1x1 convolution (matmul), W=1, and:
- `C` = Kta (aligned input channels)
- `H` = M4 (padded batch size)
- `C2` = 8 (8-byte grouping for fp16 = 4 elements per group)
- `c` = input channel (1..K)
- `h` = batch index (1..M)

When used as a `uint16_t*` index, `feature_data_off` returns a value that
gives the correct byte offset for fp16 data. For M=1, this collapses to
a simple linear layout (element k at index k-1). For M=4, it interleaves
batch elements in 8-byte groups.

### Output layout

Same function, but with `C = N`, `H = M4`, `C2 = 4` (4-byte grouping for
fp32 output = 1 element per group), and `c = output channel (1..N)`:

```c
out32[(m-1)*N + (n-1)] += om[feature_data_off(N, M4, 1, 4, n, m, 1)];
```

The `+=` is for K-tiling: when K > 768, the matmul is split into tiles and
the outputs are accumulated.

## 5. Critical Hardware Constraints

### M must be a multiple of 4

The CNA 1x1 convolution processes data in batches of 4 internally. M=1, 2, 3
produce **completely wrong results**. Only M=4, 8, 12, ... are correct.

**Fix**: Always pad M to `M4 = max(4, ((M + 3) / 4) * 4)`:
- Zero-fill the input BO for all M4 rows
- Copy real input data into the first M rows only
- Program the CNA with M4 (pass M4 to `cna_gen_task`)
- Read only the first M rows of the output

```c
int M4 = M;
if (M4 < 4) M4 = 4;
if (M4 % 4) M4 = ((M4 + 3) / 4) * 4;

// Zero the padded input
memset(im, 0, M4 * Kt * 2 + 4096);
// Fill only real rows
for (int m = 1; m <= M; m++)
  for (int k = 1; k <= Kt2; k++)
    im[feature_data_off(Kta, M4, 1, 8, k, m, 1)] = x[(m-1)*K + sk];

// Submit with M4
cna_submit_wt(c, M4, Kta, N, wt_dma);

// Read only M rows
for (int m = 1; m <= M; m++)
  for (int n = 1; n <= N; n++)
    out32[(m-1)*N + (n-1)] += om[feature_data_off(N, M4, 1, 4, n, m, 1)];
```

**BO sizes must account for M4**, not M:
```c
int M4 = ((M + 3) / 4) * 4; if (M4 < 4) M4 = 4;
cna_create_bo(fd, M4 * in_Kt * 2 + 4096, ...);  // input
cna_create_bo(fd, M4 * max_N * 4 + 4096, ...);  // output
```

### K > 768 requires tiling

The CNA CBUF can hold at most 768 input channels at a time. For K > 768
(e.g., 3072 in the down-projection of ViT), the matmul is split into tiles:

```c
int Kt = K > 768 ? 768 : ((K + 31) / 32) * 32;
int n_tiles = (K + Kt - 1) / Kt;

for (int t = 0; t < n_tiles; t++) {
  int ks = t * Kt;               // start of this tile's K range
  int ke = ks + Kt; if (ke > K) ke = K;
  int Kt2 = ke - ks;             // actual channels in this tile
  // ... load input slice, submit, accumulate output += ...
}
```

Each tile contributes a partial sum. The output accumulates across tiles
via the `+=` in the output read.

### Cache coherency

The NPU and CPU do not share a coherent cache. You must flush CPU caches
before the NPU reads and invalidate before the CPU reads:

```c
// Before NPU reads (CPU wrote, flush to DRAM)
user_dcache_flush(ptr, size);    // dc civac + dsb sy

// After NPU writes, before CPU reads
user_dcache_flush(ptr, size);    // dc civac + dsb sy
```

The `user_dcache_flush` function uses inline ARM64 assembly:
```c
static void user_dcache_flush(void* addr, uint64_t size) {
  uintptr_t start = (uintptr_t)addr & ~63ULL;
  uintptr_t end = (uintptr_t)addr + size;
  for (uintptr_t p = start; p < end; p += 64)
    asm volatile("dc civac, %0" :: "r"(p));
  asm volatile("dsb sy" ::: "memory");
}
```

### Device exclusivity

The NPU device (`/dev/dri/card1`) is exclusive: only one fd can hold it at
a time per process. Opening a second fd while the first is open fails with
`PermissionError`. The CNA context is a singleton (`g_cna`).

## 6. Step-by-Step: Implementing a New Op

Let's say you want to implement a **batched matmul with bias add** — `Y = X @ W + B`.

### Step 1: Extend the register task

The CNA has a "post-processing" stage in the DPU (data processing unit)
that can add a bias. But for simplicity, we'll add the bias on the CPU
after reading the NPU output:

```c
__attribute__((visibility("default")))
int npu_cna_mm_bias(int w_idx, int M, const void* Xh, const float* bias,
                    int N, void* Zh32) {
  // Run the standard matmul
  int rc = npu_cna_cache_run_m(w_idx, M, Xh, Zh32);
  if (rc) return rc;

  // Add bias on CPU (output is fp32)
  float* out = (float*)Zh32;
  for (int m = 0; m < M; m++)
    for (int n = 0; n < N; n++)
      out[m * N + n] += bias[n];
  return 0;
}
```

This is the **hybrid** pattern: NPU does the heavy compute (matmul), CPU
does the lightweight elementwise (bias add). This is how production NPU
inference works.

### Step 2: For a true NPU-side bias, modify cna_gen_task

If you want the bias on the NPU itself (no CPU roundtrip), you need to
program the DPU post-processing registers. The DPU has an "EW" (elementwise)
stage that can add a constant or a per-channel bias:

```c
// In cna_gen_task, after the matmul registers:
// DPU_EW_CFG (0x4070): enable EW add
ops[75] = NPUOP(0x1001, 0x383, 0x4070);  // already set (EW enabled)
// DPU_EW_ALU0_SELECT (0x4078): select ADD
ops[77] = NPUOP(0x1001, 1, 0x4078);      // already set
// DPU_EW_CVT_SCALE (0x4084): scale = 1.0
ops[80] = NPUOP(0x1001, 1, 0x4084);      // already set
// You would also need to set the bias DMA address and size in the
// appropriate DPU registers (0x4020 area). This requires additional
// RE work to map the exact register fields.
```

> The existing `cna_gen_task` already has the EW (elementwise) stage
> configured for an identity operation (scale=1, no add). Modifying it
> to add a bias requires understanding the DPU's EW source register and
> bias DMA layout, which is beyond the current scope.

### Step 3: Export from the shared library

```c
__attribute__((visibility("default")))
int npu_cna_mm_bias(int w_idx, int M, const void* Xh,
                    const float* bias, int N, void* Zh32);
```

The `__attribute__((visibility("default")))` makes the symbol visible to
`ctypes.CDLL` and the PJRT plugin.

### Step 4: Register with the build system

Add your function to `cna_matmul.c` (or a new `.c` file concatenated by
the Makefile). Rebuild:

```bash
make full
```

The `full` target concatenates `pjrt_npu_impl.c + cna_matmul.c + lm_forward.c`
into a single compilation unit, so all functions see each other.

## 7. Integration with PyTorch

The PyTorch integration uses `ctypes` to call the C functions directly.
No PyTorch C++ extension is needed — the NPU matmul is just a function call.

### Basic pattern

```python
import ctypes
import numpy as np

# Load the plugin
plugin = ctypes.CDLL("/path/to/libpjrt_npu.so")

# Set up C function signatures
plugin.npu_cna_cache_setup.restype = ctypes.c_int
plugin.npu_cna_cache_setup.argtypes = [ctypes.c_int] * 4
plugin.npu_cna_cache_load.restype = ctypes.c_int
plugin.npu_cna_cache_load.argtypes = [ctypes.c_int, ctypes.c_void_p,
                                       ctypes.c_int, ctypes.c_int]
plugin.npu_cna_cache_run_m.restype = ctypes.c_int
plugin.npu_cna_cache_run_m.argtypes = [ctypes.c_int, ctypes.c_int,
                                       ctypes.c_void_p, ctypes.c_void_p]
plugin.npu_cna_close.restype = None

# Setup: 4 weights, max M=197 (sequence), max K=768, max N=3072
plugin.npu_cna_cache_setup(4, 197, 768, 3072)

# Load weights (fp16, row-major [K, N])
W_qkv = np.random.randn(768, 2304).astype(np.float16) * 0.02
plugin.npu_cna_cache_load(0, W_qkv.ctypes.data_as(ctypes.c_void_p), 768, 2304)

# Run matmul: X [M, K] fp16 -> Y [M, N] fp32
X = np.random.randn(197, 768).astype(np.float16)
Y = np.zeros(197 * 2304, dtype=np.float32)
plugin.npu_cna_cache_run_m(0, 197,
                           X.ctypes.data_as(ctypes.c_void_p),
                           Y.ctypes.data_as(ctypes.c_void_p))
Y = Y.reshape(197, 2304)

plugin.npu_cna_close()
```

### The npu_matmul helper

For multi-dimensional inputs (e.g., `[1, 197, 768]`), flatten to 2D, run,
then reshape:

```python
def npu_matmul(x, w_idx):
    """x: [..., K] fp32 or fp16 -> [..., N] fp32"""
    orig_shape = x.shape
    K = orig_shape[-1]
    M = int(np.prod(orig_shape[:-1]))
    x2d = np.ascontiguousarray(x.reshape(M, K), dtype=np.float16)
    out = np.zeros(M * 4096, dtype=np.float32)  # oversized; NPU writes M*N
    plugin.npu_cna_cache_run_m(w_idx, M,
                               x2d.ctypes.data_as(ctypes.c_void_p),
                               out.ctypes.data_as(ctypes.c_void_p))
    return out.reshape(orig_shape[:-1] + (-1,))
```

### Loading weights from HuggingFace

```python
import torch
```

## 8. Integration with JAX

JAX integration uses the PJRT C plugin. The CNA matmul is exposed as a
JAX custom op (`npu_cached_mm`) that lowers to a `stablehlo.custom_call`.

### The custom op definition

In `src/opennpu/jax_npu.py`:

```python
import jax
from jax._src import core as core
from jax._src.interpreters import mlir

npu_mm_p = core.Primitive("npu_cached_mm")

def _abstract(x, *, w_idx, out_n=None):
    out_shape = list(x.shape)
    out_shape[-1] = out_n  # N is known from the loaded weight
    return core.ShapedArray(tuple(out_shape), x.dtype)

npu_mm_p.def_abstract_eval(_abstract)

def _lower(ctx, x, *, w_idx, out_n=None):
    aval = ctx.avals_in[0]
    out_shape = list(aval.shape)
    out_shape[-1] = out_n
    result_ty = mlir.ir.RankedTensorType.get(out_shape, mlir.ir.F16Type.get())
    op = mlir.custom_call(
        "npu_cached_mm",
        result_types=[result_ty],
        operands=[x],
        backend_config=f"w_idx={w_idx}",
    )
    return [op.result]

mlir.register_lowering(npu_mm_p, _lower)

def npu_cached_mm(x, w_idx, out_n=None):
    return npu_mm_p.bind(x, w_idx=w_idx, out_n=out_n)
```

### How the C plugin handles it

In `pjrt_npu_impl.c`, the compiler detects `npu_cached_mm` in the MLIR
bytecode and sets `ex->op = 7` with `ex->w_idx` parsed from the
`backend_config` string:

```c
if (HAS("npu_cached_mm", 13)) {
    ex->op = 7;
    ex->w_idx = -1;
    // Parse "w_idx=N" from backend_config
    const char* wp = NULL;
    for (size_t i = 0; i + 6 <= n; i++)
        if (!memcmp(c + i, "w_idx=", 6)) { wp = c + i + 6; break; }
    if (wp) { int v = 0; while (*wp >= '0' && *wp <= '9') { v = v*10 + (*wp-'0'); wp++; } ex->w_idx = v; }
}
```

At execute time, the plugin reads the weight dimensions from the CNA cache
and calls `npu_cna_cache_run_m`:

```c
if (ex->op == 7) {
    if (npu_cna_ready()) {
        int K = npu_cna_wt_k(ex->w_idx);
        int N = npu_cna_wt_n(ex->w_idx);
        int M = Xb->bo.size / 2 / K;  // fp16: size/2 = M*K
        float* Z32 = malloc(M * N * 4);
        npu_cna_cache_run_m(ex->w_idx, M, Xb->bo.mm, Z32);
        // Convert fp32 -> fp16, create output buffer
    }
}
```

### Setting up the CNA cache before JAX

The CNA weight cache is a **global singleton** in the plugin. You must
set it up via `ctypes` before JAX execution:

```python
import ctypes
plugin = ctypes.CDLL("/path/to/libpjrt_npu.so")

# Must match the number of npu_cached_mm calls in your JAX function

# Now JAX can use npu_cached_mm

# ... define and jit your function ...
```

## 9. Weight Pre-tiling for K > 768

The CNA CBUF holds at most 768 input channels. For K > 768, weights are
split into tiles of Kt=768 channels each:

```c
int Kt = K > 768 ? 768 : ((K + 31) / 32) * 32;
int n_tiles = (K + Kt - 1) / Kt;
int tile_elems = N * Kta;  // Kta = Kt rounded to 32
int tile_bytes = tile_elems * 2;
int total_bytes = n_tiles * tile_bytes + 4096;

// Allocate one weight BO holding all tiles
cna_create_bo(fd, total_bytes, CNA_FLAGS_WT, &wt_h, &wt_obj, &wt_dma, &wt_mm);

// Tile the weight into the BO
uint16_t* wm = (uint16_t*)wt_mm;
for (int t = 0; t < n_tiles; t++) {
    int ks = t * Kt, ke = ks + Kt; if (ke > K) ke = K;
    int Kt2 = ke - ks;
    int Kta2 = ((Kt2 + 31) / 32) * 32;
    uint16_t* tile = wm + t * tile_elems;
    for (int n = 1; n <= N; n++)
        for (int k = 1; k <= Kt2; k++) {
            int sk = ks + k - 1;
            if (sk < K)
                tile[weight_fp16_off(Kta2, n, k)] = w[sk * N + (n - 1)];
        }
}
```

At run time, each tile is submitted separately, and the output
accumulates:

```c
for (int t = 0; t < n_tiles; t++) {
    uint64_t wt_dma_tile = wt_dma + (uint64_t)t * tile_bytes;
    cna_submit_wt(c, M4, Kta, N, wt_dma_tile);
    // output += partial result from this tile
}
```

## 10. Verification Methodology

### Always verify with random weights, not identity

The identity matrix `I` has `I^T = I`, so it masks transpose bugs. Always
test with random weights:

```python
np.random.seed(42)
W = np.random.randn(K, N).astype(np.float16) * 0.1
X = np.random.randn(M, K).astype(np.float16)

# NPU result
out_npu = npu_matmul(X, w_idx)

# CPU reference
out_cpu = X.astype(np.float32) @ W.astype(np.float32)

# Check
diff = np.max(np.abs(out_npu - out_cpu))
assert diff < 0.01, f"FAIL: diff={diff}"
print(f"OK: max diff = {diff:.6f}")
```

### Test multiple M values

The M-multiple-of-4 constraint is not obvious. Test M=1, 2, 3, 4, 5, 8:

```python
for M in [1, 2, 3, 4, 5, 8, 16, 64]:
    out = npu_matmul(X[:M], w_idx)
    cpu = X[:M].astype(np.float32) @ W.astype(np.float32)
    diff = np.max(np.abs(out - cpu))
    print(f"M={M}: diff={diff:.6f} {'OK' if diff < 0.01 else 'FAIL'}")
```

### Test non-square shapes

Square weights mask the transpose bug. Always test K != N:

```python
for K, N in [(768, 2304), (768, 3072), (3072, 768), (32, 16)]:
    # ... load W[K, N], run X[M, K] @ W, compare ...
```

### End-to-end model verification

For a full model, compare the NPU logits against a CPU reference:

```python
import torch
from transformers import GPT2LMHeadModel

model = GPT2LMHeadModel.from_pretrained("gpt2").eval()
ids = tokenizer("The future of AI is")["input_ids"]

with torch.no_grad():
    cpu_logits = model(torch.tensor([ids])).logits[0, -1].numpy()

npu_logits = npu_model.prefill(ids)

diff = np.max(np.abs(npu_logits - cpu_logits))
print(f"Max abs diff: {diff:.4f}")
print(f"Argmax match: {np.argmax(npu_logits) == np.argmax(cpu_logits)}")
```

Expected: diff < 0.1 (fp16 rounding), argmax match = True.

## 11. Troubleshooting

### NPU output is all zeros

- Did you flush the input BO cache before submit? (`user_dcache_flush`)
- Did you flush the output BO cache after submit?
- Is the weight BO loaded and flushed?
- Are the DMA addresses correct (not CPU virtual addresses)?

### NPU output is wrong but shape is correct

- **Weight transpose bug**: Check `w[sk*N + (n-1)]`, not `w[(n-1)*K + sk]`.
- **M not a multiple of 4**: Pad M to M4, program CNA with M4.
- **Wrong feature_data_off H parameter**: Use M4 (padded), not M.
- **Cache coherency**: Add `user_dcache_flush` calls.

### Segfault on large M

- BOs are too small. Allocate for M4 (padded), not M.
- Output BO: `M4 * max_N * 4 + 4096`, not `M * max_N * 4 + 4096`.

### `PermissionError` on `open("/dev/dri/card1")`

- The NPU is exclusive. Only one fd per process.
- Kill any lingering NPU processes: `sudo fuser -k /dev/dri/card1`.
- After a submit timeout, the SBC must be rebooted (kernel bug).

### Submit timeout / NPU hang

- Use `flags = 1 | 4` (non-blocking) in the submit ioctl.
- If the NPU hangs, reboot the SBC.
- Check that the regcmd BO has 112 entries and the task header is correct.

### JAX `custom_call` output shape is wrong

- The `out_n` parameter in `npu_cached_mm` must match the loaded weight's N.
- Use `register_weight_n(w_idx, n)` for global registration.
- Multi-op programs with mixed custom_calls + jnp ops are experimental.
- For complex shapes, use the ctypes path instead.

### Build contamination

If `make full` fails, the Makefile's restore sequence doesn't execute,
leaving the concatenated file in place. Clean and redeploy:

```bash
rm -f src/opennpu/pjrt_c/_impl_full.c src/opennpu/pjrt_c/pjrt_npu_impl_orig.c
git checkout src/opennpu/pjrt_c/pjrt_npu_impl.c
make full
```
